# oapi-codegen — Spec-Driven JSON Endpoints

Use this when adding or changing any JSON endpoint in Politburo. SSR routes (`/auth/*`, `/dashboard`, `/maps/*`, `/operator/*` HTML, `/static/*`) are never in OpenAPI. Read `.claude/commands/architecture.md` first for layout and lookouts.

---

## Files

```
openapi/politburo/                       # SOURCE — edit these
  openapi.yaml                           # info, servers, path index, securitySchemes, schema index
  paths/<area>/<name>.yaml               # one path item per file (health/, game/, auth/, ...)
  components/schemas/<Name>.yaml         # one schema per file; file name == component name
openapi/politburo.yaml                   # BUNDLE — generated by Redocly, committed, never hand-edit
cicd/codegen/politburo-oapi-codegen.yaml # package politburoapi; models + chi-server
cicd/package.json                        # pinned @redocly/cli
cicd/tools/go.mod                        # pinned oapi-codegen (go tool)
services/politburo/internal/api/generated/politburo/server.gen.go      # gitignored output
services/comrade-bot-discord/src/generated/politburo-api.ts            # gitignored output
```

One contract for the whole Politburo public API. Do **not** create per-domain spec files or per-domain codegen configs. Keep the upstream Infinite Flight spec (`openapi/infinite-flight/`) separate.

## Adding an operation

1. **Path file** — `openapi/politburo/paths/<area>/<name>.yaml` containing the path item (`get:`/`post:` …). Reference schemas by relative file path:
   ```yaml
   get:
     operationId: getActiveFlights          # camelCase; becomes the Go method name (GetActiveFlights)
     summary: Read cached active Infinite Flight flights for a server
     security:
       - ApiKeyAuth: []
       - CookieAuth: []                     # only for paths AuthenticateAPI accepts sessions on (/api/v1/game/**, /api/v1/operator/**)
     responses:
       "200":
         description: ...
         content:
           application/json:
             schema:
               $ref: "../../components/schemas/ActiveFlightsResponse.yaml"
       "401":
         description: Missing or inactive API key or session cookie
         content:
           application/json:
             schema:
               $ref: "../../components/schemas/ErrorResponse.yaml"
   ```
2. **Schema files** — `openapi/politburo/components/schemas/<Name>.yaml`. Between schemas use `$ref: "./Other.yaml"`.
3. **Index** — add the path under `paths:` and every new schema under `components.schemas:` in `openapi/politburo/openapi.yaml` (keeps bundle order stable and makes the root a table of contents).
4. **Generate** — from repo root: `make generate` (bundles, then Go + TS). Commit sources **and** `openapi/politburo.yaml`.
5. **Implement** — see below. `make check` to run Politburo tests.

Security schemes available: `ApiKeyAuth` (`X-API-Key` header), `CookieAuth` (`session_id` cookie). Discord context headers (`X-Discord-User-Id`, `X-Discord-Server-Id`) are modeled as header **parameters**, not security schemes.

## Response shapes (match the Go writers exactly)

| Case | Shape | Go writer |
|---|---|---|
| Error (all non-2xx) | `{ "error": { "code": string, "message": string } }` → `ErrorResponse.yaml` | `response.WriteError(w, status, code, message)` |
| Plain success | `{ "data": <Payload> }` (e.g. `GenerateSignedLinkResponse`) | `response.WriteJSON(w, status, body)` |
| Cache-backed success | `{ "data": { availableFilters, result, history?, meta, pagination? } }` | `cachedresponse.Response[T]` |
| Health | `HealthResponse` (no envelope) | health handler |

There is no `{status, result, responseTimeMs}` envelope in the rewrite — that was the legacy `httpdto` shape.

Rules:
- `required` lists every field Go always emits; `omitempty`/pointer fields are not required.
- Arrays that Go encodes as `[]` stay `type: array` (never nullable).
- Timestamps `format: date-time`; UUIDs `format: uuid`; enums copied from Go constants.
- Describe every status the handler can actually return (typically 400 filter/validation, 401, 403 missing Discord context, 404, 500, 503 cache unavailable).

## Implementing against the generated server

Politburo uses the **non-strict** chi server (`ServerInterface` with `(w, r, params)` methods). There is no `StrictServerInterface`, no request-validator middleware, and no `NewStrictHandler`.

1. Handler in `services/politburo/internal/transport/http/api/<feature>/handler.go`, constructed with its dependencies from `app.App`.
2. Add a method on `apiHandler` in `internal/transport/http/server.go` that converts generated params to plain Go values and delegates:
   ```go
   func (h apiHandler) GetActiveSessions(w stdhttp.ResponseWriter, r *stdhttp.Request, params politburoapi.GetActiveSessionsParams) {
       h.sessions.GetActiveSessions(w, r, params.History)
   }
   ```
   Handlers and domain packages must not import generated types beyond this adapter.
3. Auth is applied globally by `AuthenticateAPI` (all `/api/v1`). Extra gates (Discord context, membership, roles, operator) are route-group middleware — if an operation needs them, it cannot go through the shared `HandlerWithOptions` mount without per-route wrapping; plan that explicitly.
4. Parameter binding errors go through `writeParameterError` → 400 `INVALID_QUERY_FILTER`.

## Bot side

After `make generate`, `src/generated/politburo-api.ts` has `paths`/`components` types. Bot HTTP stays in `src/services/apiService.ts`; prefer importing generated types there over extending hand-written `src/types/Responses.ts`.
